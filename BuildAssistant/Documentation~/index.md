# ビルド実行アシスタント 1.1.0

ビルド実行アシスタントは、Unityのデスクトップ向け通常プレイヤーについて「何を、どこへビルドするか」を実行前に記録し、確認済みの計画に従ってプレイヤーを一度だけ新しいフォルダーへ出力するエディター専用モジュールです。

## 操作の流れ

`Tools > ビルド実行アシスタント > 開く`を開き、次の順番を変えずに操作します。

1. 「① ビルド設定」で有効なビルドプロファイルと「エディターで選択中の対象機種」を確認します。
2. 「② 出力先」で「出力先ルート」を指定します。
3. 「③ 計画作成」で「ビルド計画を作成」を押します。
4. 「④ 実行確認」で取得内容を確認し、「ビルド設定、シーン、選択肢、出力先を確認しました。」を有効にします。
5. 「⑤ 実行結果と書き出し」で「確認済みの計画を実行」を押します。

## ① ビルド設定

画面は、Unityで現在有効なビルドプロファイルと、エディターでコンパイル済みの対象機種を表示します。本モジュール自身はビルドプロファイル、`EditorUserBuildSettings`、`PlayerSettings`、対象機種を切り替えません。

対応する対象機種は次の三つです。

- `StandaloneWindows64`
- `StandaloneOSX`
- `StandaloneLinux64`

通常プレイヤー用のクライアント種別だけに対応します。専用サーバー、32ビットWindows、モバイル、ウェブ、コンソールは対象外です。必要なプラットフォームモジュールを導入済みで、`BuildPipeline.IsBuildTargetSupported`が利用可能と報告する必要があります。

`ProfilerUserSettings.customConnectionID`に値がある場合に追加される`BuildOptions.CustomConnectionID`も対象外です。確認表示と実行内容が一致しない状態を避けるため、計画作成前に拒否します。

### 独自のビルドプロファイル

独自のビルドプロファイルは、プロジェクト内に保存済みで、有効なGUIDと依存関係ハッシュを取得できる必要があります。

プロファイルが指定する対象機種とクライアント・サーバー種別は、エディターで選択中の内容と一致していなければなりません。`Default`と`Player`は、どちらも通常プレイヤーを表す場合に限り同じ種別と見なします。不一致時は`BuildTargetMismatch`として計画を作りません。「ビルドプロファイルを開く」でUnityの画面へ移動し、対象を切り替え、コンパイル完了後に計画を作り直してください。

この条件により、別対象向けの組み込みコンパイル記号が残った状態で独自プロファイルを実行することを防ぎます。

## ② 出力先

「出力先ルート」には完全な絶対パスを指定します。指定可能な形は次の二つです。

- すでに存在するフォルダー
- すでに存在するフォルダー直下の、まだ作られていないフォルダー一つ

二階層以上を一度に作るパス、既存ファイル、ドライブ相対パスは拒否します。OSがローカルの固定ファイルシステムとして報告する場所だけを許可し、UNC、ネットワークドライブ、割り当てドライブ、判定できないファイルシステムは拒否します。

プロジェクトの`Assets`、`Packages`、`ProjectSettings`、`Library`、`Temp`、`Logs`、`obj`と同じ場所、その内側、それらを含む場所は利用できません。

### パスの検査

Windowsでは、大文字と小文字を同一視し、既存フォルダーの物理的な正規経路を確認します。`\\?\`や`\\.\`の機器名経路、代替データストリームを表す余分な`:`、予約機器名、再解析点を拒否します。

LinuxとmacOSでは大文字と小文字を区別します。候補とUnity管理フォルダーの既存祖先について、機器番号とファイル識別子を比較し、同じ実体を指す別名を拒否します。大文字小文字だけが異なる非固定マウントとの一致が曖昧な場合も、安全を確認できないため拒否します。

Linuxでは`/proc/self/mountinfo`からファイルシステム識別子と内部位置を解決し、Unity管理フォルダー全体だけでなく、その下位を指すバインドマウントも拒否します。macOSではこのLinux固有情報を使わないため、既存フォルダーと祖先の物理識別子で確認できる範囲が保証境界です。

## ③ 計画作成

「ビルド計画を作成」は読み取りだけを行います。出力フォルダー、履歴、実行状態を作成せず、Unityの設定も変更しません。

計画には次の情報を記録します。

- ビルドプロファイルの種類、GUID、アセットパス、名前、依存関係ハッシュ
- 対象機種、対象群、名前付き対象、種別、コード生成方式
- 実際に適用されるビルド選択肢、コンパイル記号、アセットバンドル目録のパス
- ビルドシーンの順序、有効状態、GUID、アセットパス、依存関係ハッシュ
- `ProjectSettings`以下の設定ファイル
- `Library/BuildProfiles`以下のプロファイル設定ファイル
- `Library/EditorUserBuildSettings.asset`
- `AssetDatabase.GlobalArtifactDependencyVersion`と`AssetDatabase.GlobalArtifactProcessedVersion`
- `Packages/manifest.json`と`Packages/packages-lock.json`
- `Assets/StreamingAssets`以下のファイル名と内容
- 正規化した出力先ルート、今回の実行フォルダー、プレイヤー出力
- 条件が一致する直近の成功結果

各ファイルの記録は、形式番号、件数、パス長、内容長を含む照合値へまとめます。ファイルの追加、削除、並べ替え、内容変更を区別します。

有効なシーンは`Assets`または`Packages`以下の正規化済み`.unity`パスで、存在し、`SceneAsset`として読み込めて、有効なGUIDと依存関係ハッシュを持つ必要があります。無効なシーンは確認情報として保持しますが、ビルド対象には渡しません。

## ④ 実行確認

「ビルドプロファイル」「取得した入力照合値」「対象機種」「コード生成方式」「ビルド選択肢」「有効なシーン」「出力先ルート」「今回の実行フォルダー」「プレイヤー出力」を確認します。出力先を変更すると、計画と確認状態は破棄されます。

独自のビルドプロファイルが持つ圧縮方式や開発用設定は、実際に適用されるビルド選択肢として確認画面、履歴、比較条件へ含めます。実行時はUnityの`BuildPlayerWithProfileOptions`がプロファイルから適用するため、同じ値を追加指定して二重に上書きしません。

## ⑤ 実行結果と書き出し

実行開始時は次の順に検査します。

1. 本モジュール内とUnity内で、別のプレイヤービルドが動いていないことを確認します。
2. Unityがコンパイル、更新、再生モードへの切り替え中でないことを確認します。
3. 履歴に有効な主・予備ファイルがあることを確認し、前回から残った実行状態を安全に復旧します。
4. 計画作成時の入力を再取得し、一致することを確認します。
5. 新しい実行フォルダーを排他的に作成します。
6. 実行中状態を`Library/BuildAssistant`へ保存します。
7. 出力先の経路、予約情報、再解析点、空の実行フォルダー、プレイヤー出力を再確認します。
8. Unityのビルド処理を一回だけ呼び出します。

実行フォルダー名は`BA-yyyyMMdd-HHmmss-8hex`形式です。予約ファイルとフォルダーは新規作成だけを許し、既存の実行フォルダー、既存プレイヤー、予約後に追加されたファイルがあれば上書きせず停止します。本モジュールは以前の実行フォルダーを削除しません。

Windowsでは実行中に削除共有を許可しないフォルダーハンドルを保持し、開始前に物理的な正規経路を再確認します。Unix系では排他的な`mkdir`で通常の同名作成競合を防ぎますが、権限を持つ外部処理が同時に行う意図的な再マウント、置換、権限変更までは保証しません。

### ビルド前処理での再検査

Unityのビルド前処理による入力変更や出力先への内容追加も検出するため、本モジュールは`IPreprocessBuildWithReport`を`callbackOrder = int.MaxValue`で登録します。本モジュールより前に実行された同種の前処理が記録対象を変更した場合は`StalePlan`、予約済み実行フォルダーへ内容を追加した場合は出力先の競合としてビルドを中止します。再取得や再検査自体に失敗した場合も安全側に中止します。

この検査には順序上の境界があります。同じ`int.MaxValue`を持ち本検査より後に選ばれた同種の処理、別の種類として後から動く処理、外部処理による非同期変更は検出を保証できません。「確認済みの計画」は、記録対象の入力と予約済み出力先について、実行要求直後および上記の前処理検査時点までの一致を意味します。

## 結果と容量

Unityが返した`BuildReport`は、その場で通常のC#値へ縮約します。Unityオブジェクトや過去の`BuildReport`を保持せず、`GetLatestReport`も使用しません。

保存する主な情報は次のとおりです。

- 成功、失敗、中断
- 開始日時、完了日時、所要時間
- 警告数、エラー数
- 出力全体、格納内容、格納付加分の容量
- アセット別、型別の格納容量
- 比較可能な直近成功結果との差

比較対象は、プロファイルの識別情報、対象機種、対象機種群、名前付き対象、種別、コード生成方式、実際に適用されるビルド選択肢が一致する、保存順で直近の成功結果です。OSの時計が戻っても完了時刻だけで以前の結果へ戻りません。シーン内容は比較対象を選ぶ条件へ含めません。

容量内訳の読み取りだけが失敗しても、Unityが成功を報告した事実は失敗へ書き換えません。ビルド成功と履歴保存成功も別に返します。

## 履歴と中断復旧

履歴と実行状態はプロジェクトの`Library/BuildAssistant`へ保存します。

- `history.json`: 新しい順に最大20件
- `history.json.bak`: 更新前の予備
- `run-state.json`: 実行中または完了済みの一時状態
- `run-state.json.bak`: 実行状態の予備
- 各`.tmp`: 同じフォルダー内で置き換えるための一時ファイル

一時ファイルへの書き込みと同期を終えてから、主ファイルと予備を入れ替えます。主ファイルが壊れている場合や、存在確認または読み込みを拒否された場合は、形式と内容を検査した予備から読み込みます。

履歴と実行状態はUTF-8で書き出します。読み込みは開始時のファイル容量だけに頼らず、入力保持領域を16MiB以下へ固定するため、読み込み中に内容が増えても上限を超えた部分を保持・復元しません。文字順印付きの既存文書も読み込めますが、UTF-8へ復元した内容が16MiBを超える場合は受理しません。一件あたりのコンパイル記号とシーンは各4096件、アセットは100000件、型は32768件までです。必要な文字列、プロファイル識別情報、連続するシーン順、時刻順、列挙値、本モジュールが対応するビルド設定の組み合わせ、件数、発生回数、状態と失敗理由、出力先からプレイヤー出力までの包含関係も検査します。1.0.0が書き出した同じ構造は、空名の独自プロファイルを含めて現在の容量・件数上限内なら読み戻せます。上限超過や矛盾がある主ファイルは使わず、有効な予備があればそちらを使います。

Unityが`BuildPipeline.isBuildingPlayer`を報告している間は、画面の再読込やドメイン再読込が起きても実行状態を中断として回収しません。ビルド終了後、未完了状態だけが残っていれば中断として履歴へ追加します。同じ実行識別子の成功または失敗がすでに保存済みなら、古い実行中状態より保存済みの終了結果を維持します。自動再実行はしません。

履歴または実行状態について、有効な主ファイルも予備ファイルもない場合は削除も上書きもせず、`.invalid-識別子`を付けた別名へ隔離します。その実行要求は停止し、利用者が`Library/BuildAssistant`を確認して新しい計画を作れるようにします。有効な主または予備が残っている場合は隔離しません。

履歴保存に失敗した現在の結果は、保存済み履歴とは別に画面上へ保持します。同じ実行識別子だけでは保存済みと見なさず、状態、失敗理由、時刻、出力、容量まで一致する終了結果を復旧できた場合だけ保存済みへ切り替えます。

履歴が上限20件に達した後でOSの時計が過去へ戻っても、現在の結果または復旧中の結果を保存順の先頭へ置き、それまでの保存順から19件を保持します。完了時刻だけで今回結果を捨てたり、比較対象を未来時刻が残る以前の実行へ戻したりしません。

## JSON書き出し

「選択した結果を新しいJSONへ書き出す」は、選択した一件を形式番号1のJSONとして新規作成します。

- `.json`で終わる安全な絶対パスだけを受け付けます。
- 親フォルダーは存在し、出力先と同じローカル固定領域、Unity管理フォルダー除外、再解析点除外の条件を満たす必要があります。
- Windowsでは書き込み中に親フォルダーの削除共有を許可しないハンドルを保持します。
- 既存ファイルは上書きしません。
- 新規作成後の書き込みに失敗した場合は、自分で作った不完全なファイルを可能な範囲で削除します。
- 書き出し時刻など、その場で変化する余分な値は追加しません。
- 書き出し文書にも16MiBの上限を適用します。

## 公開API

名前空間は`BuildAssistant.Editor`です。

```csharp
BuildAssistantPlan plan = BuildAssistantService.Preview(absoluteOutputRoot);
BuildAssistantBuildResult result = BuildAssistantService.Build(plan);
BuildAssistantHistory history = BuildAssistantService.LoadHistory();
BuildAssistantError error = BuildAssistantService.ExportJson(entry, absoluteNewJsonPath);
```

公開される計画、結果、履歴、シーン、容量データは、作成後に内容が変わらない値です。公開コレクションは呼び出し元の配列を保持せず、読み取り専用の複製を返します。計画にUnityオブジェクトは保持しません。

## 主な失敗理由

| 値 | 意味 |
|---|---|
| `InvalidOutputRoot` | 出力先が空、相対パス、ファイル、または未作成階層が深すぎます。 |
| `UnsafeOutputPath` | Unity管理フォルダー、再解析点、ネットワーク領域など、安全条件を満たしません。 |
| `UnsupportedBuildTarget` | 対象機種、種別、プラットフォームモジュール、プロファイル、またはビルド選択肢が対応範囲外です。 |
| `BuildTargetMismatch` | 独自のビルドプロファイルと、エディターでコンパイル済みの対象機種または種別が一致しません。 |
| `EditorBusy` | Unityがコンパイル、更新、再生モード切り替え中です。 |
| `NoEnabledScenes` | 有効なビルドシーンがありません。 |
| `StalePlan` | 計画作成後またはビルド前処理中に、検査対象の入力が変わりました。 |
| `BuildAlreadyRunning` | 本モジュールまたはUnityがすでにプレイヤーをビルド中です。 |
| `OutputAlreadyExists` | 実行フォルダー、予約、プレイヤー出力、またはJSONがすでに存在します。 |
| `OutputReservationFailed` | 出力先または実行状態を安全に予約できません。 |
| `BuildInvocationFailed` | Unityのビルド処理を開始できないか、実行中に例外が発生しました。 |
| `BuildReportUnavailable` | Unityから`BuildReport`が返りませんでした。 |
| `ReportReadFailed` | `BuildReport`の容量情報を通常の値へ縮約できませんでした。 |
| `HistoryWriteFailed` | 履歴、実行状態、または明示的なJSONを永続保存できませんでした。 |

## 検証済み範囲

1.1.0のWindows向け配布前検証では、計画比較、対象機種の不一致、ビルド前処理の入力・出力再検査、出力予約、各保存段階の失敗、時計巻き戻し、履歴の上限・必須項目・値種別・意味検査・旧版固定形式の互換・復旧、読み込み中の容量増加、未保存結果の保護、表示処理を編集モード試験187件で確認しました。さらに実際のWindows 64ビット向けビルドで、履歴の作成・開始・完了時刻の順序、成果物の存在、実行状態の後片付け、描画範囲の不整合とC#コンパイル異常がないことを確認しました。Linuxのマウント情報は解析試験を含みますが、実際のLinux・macOS上でのビルド、実際のバインドマウント、ビルド中のドメイン再読込、別拡張によるビルド前処理との組み合わせは環境別の追加確認事項です。
