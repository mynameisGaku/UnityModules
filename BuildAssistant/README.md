# ビルド実行アシスタント

## 30秒で分かる説明

Unityのデスクトップ向け通常プレイヤーについて、設定確認、計画作成、明示確認、実行、履歴保存を上から順に進めるエディター専用モジュールです。

「ビルド計画を作成」で現在の設定と入力を記録し、内容を確認した計画だけを「確認済みの計画を実行」で一度だけ使用します。計画作成後やビルド前処理中に検査対象の入力が変わった場合や、予約済みの出力先へ内容が追加された場合は、ビルドを中止して計画の作り直しを求めます。

## 主な機能

- 現在有効なビルドプロファイル、対象機種、コード生成方式、ビルド選択肢、シーン、出力先を一画面で確認できます。
- 独自のビルドプロファイルと、エディターでコンパイル済みの対象機種・種別が違う場合は計画を作りません。
- 実行ごとに新しいフォルダーを作り、既存ファイルや過去の実行結果を上書きも削除もしません。
- 結果、所要時間、警告・エラー数、容量内訳、前回との容量差を新しい順に最大20件保存します。
- 選択した結果を新しいJSONファイルへ書き出します。既存のJSONは上書きしません。
- Unityのビルド設定やビルドプロファイルを自動では切り替えません。

## 対応範囲

- Unity `6000.5.7f1`
- エディター専用
- `StandaloneWindows64`、`StandaloneOSX`、`StandaloneLinux64`
- 通常プレイヤー用のクライアント種別
- `BuildPipeline.IsBuildTargetSupported`が利用可能と報告する、導入済みのプラットフォームモジュール

専用サーバー、32ビットWindows、モバイル、ウェブ、コンソールは1.1.0の対象外です。`ProfilerUserSettings.customConnectionID`を使う`BuildOptions.CustomConnectionID`も、確認表示と実行内容のずれを防ぐため計画作成時に拒否します。

## 使い方

Unityメニューの`Tools > ビルド実行アシスタント > 開く`を開き、次の順に進めます。

1. 「① ビルド設定」で有効なビルドプロファイルと対象機種を確認します。
2. 「② 出力先」で「出力先ルート」を入力するか「参照」から選びます。
3. 「③ 計画作成」で「ビルド計画を作成」を押します。
4. 「④ 実行確認」で表示内容を確認し、「ビルド設定、シーン、選択肢、出力先を確認しました。」を有効にします。
5. 「⑤ 実行結果と書き出し」で「確認済みの計画を実行」を押します。

独自のビルドプロファイルを使う場合は、プロファイルの対象機種とクライアント・サーバー種別を、エディターで選択中の内容へ一致させてください。一致しない場合は「ビルドプロファイルを開く」でUnityの画面へ移動し、切り替え後のコンパイルが終わってから計画を作り直します。`Default`と`Player`は、どちらも通常プレイヤーを表す場合に限り同じ種別として扱います。

## 出力先の条件

指定できるのは、ローカルの固定ファイルシステム上にある既存フォルダー、または既存フォルダー直下の未作成フォルダー一つです。UNC、ネットワークドライブ、割り当てドライブ、判定できないファイルシステムは利用できません。

プロジェクト内の`Assets`、`Packages`、`ProjectSettings`、`Library`、`Temp`、`Logs`、`obj`と重なる場所は拒否します。Windowsでは再解析点と物理的な正規経路を検査します。LinuxとmacOSでは大文字と小文字を区別し、機器番号とファイル識別子から管理フォルダーの別名を検査します。Linuxではさらに`/proc/self/mountinfo`から、管理フォルダーやその下位を指すバインドマウントも検査します。

実行フォルダーは`BA-yyyyMMdd-HHmmss-8hex`形式で排他的に新規作成します。Windowsでは実行中に削除共有を許可しないフォルダーハンドルも保持します。Unix系では通常の同名作成競合を防ぎますが、権限を持つ外部処理による実行中の意図的な再マウントや置換までは保証しません。

## 入力と出力先の再確認、保証範囲

計画には、ビルドプロファイル、対象機種、コード生成方式、ビルド選択肢、コンパイル記号、シーン、プロジェクト設定、パッケージ設定、読み込み済みアセットの変更世代、ストリーミング用アセット、出力先を照合する値を保存します。

実行要求の直後に同じ入力を再取得し、差があれば`StalePlan`で停止します。さらに、本モジュールの`IPreprocessBuildWithReport`を`callbackOrder = int.MaxValue`で動かし、それより前に実行された同種のビルド前処理による入力変更と、予約済み実行フォルダーへの内容追加を再検査します。

同じ最大順序で本検査より後に選ばれた処理、別種類のより後の処理、外部処理による非同期変更までは検出を保証できません。このため1.1.0の保証は、記録対象の入力と予約済み出力先について、上記の検査時点までに限られます。

## 履歴と復旧

履歴と実行状態はプロジェクトの`Library/BuildAssistant`へ保存します。履歴は最大20件です。各文書はUTF-8で書き出し、読み込み中に内容が増えた場合も入力保持領域とUTF-8へ復元した内容を16MiB以下へ制限します。コンパイル記号、シーン、アセット、型、プロファイル識別情報、文字列長、シーン順、時刻順、状態と失敗理由、出力パスの包含関係にも上限と整合検査を適用します。主ファイルの存在確認または読み込みが拒否された場合は主ファイルを使わず、有効な予備ファイルを試します。

Unityがプレイヤーをビルド中の間は、実行状態を中断として復旧しません。ビルド終了後の読み込みで未完了の状態だけが残っていれば中断として記録し、すでに保存済みの成功・失敗結果があればそちらを維持します。履歴または実行状態について、有効な主ファイルも予備ファイルもない場合は既存内容を上書きせず`.invalid-識別子`へ隔離し、その一回を停止します。

履歴が20件に達した後でOSの時計が過去へ戻った場合も、今回または復旧中の結果を保存順の先頭へ置き、それまでの保存順から19件を保持します。容量比較も保存順で直近の互換結果を使います。

ビルド成功と履歴保存成功は別に報告します。履歴保存に失敗しても現在の結果を画面上に保持し、新しいJSONへ書き出せます。

## スクリプトから使う場合

公開入口は`BuildAssistant.Editor.BuildAssistantService`です。

- `Preview(string absoluteOutputRoot)`
- `Build(BuildAssistantPlan plan)`
- `LoadHistory()`
- `ExportJson(BuildAssistantHistoryEntry entry, string absolutePath)`

公開される計画、結果、履歴、シーン、容量データは、作成後に内容が変わらない値です。計画は一度のビルドだけに使用してください。

詳しい失敗条件と保存形式は[詳しい説明](Documentation~/index.md)を参照してください。
